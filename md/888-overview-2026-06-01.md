## БЛОК A — Общая картина

### 1. Что такое 888 одним абзацем (по факту)

888 — **dispatcher-skill** (`~/.claude/skills/888/`), который маршрутизирует разработку AI-агентов по 5-фазному циклу ADLC (analyst → architect → implementer → qa → ops → improver) через **7 persona-skill'ов** + **3-слойный Storm Framework** enforcement (25 bash-hooks + 16 Python модулей + 9 embedded skills) + единый Q-NNN queue в `methodology-888.md` (живой документ 33K строк, 2.9 MB). Сам dispatcher **код/skill'ы не пишет** — только инициирует phase-chain через `phase-conductor.sh` и review-gates между фазами. Реально работает на ~78% задуманного: ядро (Phase 1/3/5 + Storm core + hooks + queue + cost-config) — production; Phase 2.5 implementer + Phase 4 ops + phase-chain enforcement + DACI arbiter + comparator — partial/works; cost-tracking + 5×3 структура + 4 phantom UX-hooks + atomic-write на methodology — заявлено, но не вкручено или сломано.

## БЛОК B — ADLC 5 фаз

### Phase 1 — analyst | ✅ production (217 lines)
**Что делает:** 6-field elicitation (pain · user profile · success metric · current alternative · out-of-scope · baseline measurement) + interactive-only mandate (блокирует headless context) + self-critique перед review-gate. **elicitation:** реально интерактивный через `AskUserQuestion` (после Q-260528-ANALYST-DISCIPLINE inference DISABLED — каждое поле требует явного ответа). **F8 no-deadlock escape** вкручен (парк после ≥3 пустых ответов). Review-gate: `bmad-review-adversarial-general`.

### Phase 2 — architect | 🔨 works (347 lines)
**Что делает:** 7-field checklist (single-LLM check · patterns P1-P5 · memory · tools · multi-LLM routing · threat-model placeholder · RAG) + Field 0 complexity auto-classification (5 эвристик, architect classifies — не спрашивает user). **failure modes:** в дизайне просят их перечислить, но **жёсткого enumeration-check нет** (prose-rule). threat-model placeholder-level (3 attack vectors прозой). Decision-tree для patterns описана, **реально на практике** — скорее процедурная. Review-gate: `bmad-review-edge-case-hunter`.

### Phase 2.5 — implementer | 🔨 works (231 lines)
**Что делает:** severity classification (S/M/L) → 3 пути → irreducible gate (ruff/bash -n/structural validate). **Iron Law (RED commit ДО фикса):** **НЕ enforced хуком, описано в prose** (SKILL.md ~76). `phase-conductor.sh` запускает orchestration, но Iron Law опирается на дисциплину implementer. severity_classifier.py существует, floor-правила вкручены (unknown_api/self-modify → минимум M). ### Phase 3 — qa | ✅ production (268 lines)
**Что делает:** 6-field checklist (happy paths · edge cases · red-team · pass rate target · OWASP ASI scope · merge-blocking criteria) + **Phase 3.5 Pilot Test (HITL Bootstrap, добавлено 2026-05-20)**. **7-layer pyramid — НЕ найдена явно**; вместо этого 6 полей + 3×3 матрица (happy/edge/red-team × top-3). Review-gates: `bmad-code-review` (всегда) + `bmad-security-review` (4 hunters, при security_critical).

### 25. Mode detection

**Двухслойная система:**
1. **`intent-detector.sh`** (Layer 1) — перехватывает prompt, regex/Python-классификатор, инжектит context warning, но **сам не роутит** (info-only).
2. **Dispatcher SKILL.md §1** — LLM видит mode table, disambiguates по keyword'ам:
   - Однозначно → skip menu, прямой invoke persona
   - Неоднозначно → `AskUserQuestion` disambiguation menu (Стр 1: 4 кнопки)
   - Rule: при сомнении НЕ угадывать

**Надёжность:** хороша для чётких triggers («новый агент»). Уязвима на freetext «добавь улучшение» — может быть MAINTENANCE или EXISTING. Защита через menu fallback срабатывает.

**TOP-3 used:** NEW (211) + EXISTING (42) + SELF_EXISTING (25) = 93% всего трафика. **Bottom-3 unused:** ADOPT (6) — путается с EXISTING; MAINTENANCE (7) — встроено в EXISTING flow; QUESTION (5) — read-only не требует phase cycle.
