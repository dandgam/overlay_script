4 · Почему «специально НЕТ» — сноски ¹…⁸

  1. INV-PERSIST вне гейта propagate :1607 — разлив копирует канон → проекты и не может вылечить «незакоммичено в каноне». Оставить его в гейте = гейт всегда красный = каждый правильный разлив откатывался бы.
  2. INV-PERSIST вне exit-кода revalidate :1622 — печатается в отчёте, но exit 3 только по «разливаемым» ошибкам. Та же причина, что ¹.
  3. Один golden-gate — два режима. В check провал = fail-open :1541 (warn INV-GOLDEN-GATE, канарейка молча выключается — сломанная фикстура не должна ронять байтовое ядро). В capture (◌W0.1) провал = fail-closed (HALT до commit — в источник истины вслепую не пишем). Протухшая фикстура заблокирует ВСЕ capture — осознанный размен «безопасность > доступность».
  4. Текст-канарейки нет в propagate/revalidate — они возят и сверяют байты; смысл проверяет check (и придёт в capture). Дублировать смысловую проверку при каждом разливе = двойная работа без новой информации.
  5. capture без git_guard — он пишет в vault, а не в проект. Замена: dirty-check канона в plan_capture :1020 + vault_lock :1664 + проверка «vault — git-репо» :1687.
  6. capture без ROLLBACK.json и без пост-гейта — его откат это git самого vault'а, а канарейки бьют HALT ДО commit :1666: откатывать обычно нечего.
  7. init-project / post-upgrade: авто-отката НЕТ — ROLLBACK.json пишется :1779, но rollback_install :1475 в командах не вызывается (только тесты/вручную). Асимметрия с propagate — знать при факапе!
  8. INV-FORK-SUPERSEDED = warn, а не error (решение 1.4) — лишний форк propagate не чинит; error из общего run_invariants попал бы в его гейт :1606-1607 и откатывал бы чужой правильный разлив, потребовав второй «костыль-исключение» как у INV-PERSIST.

6 · Exit-коды (общие для всех команд)

0 OK
чисто (или dry-run показал план)
1 WARN
есть предупреждения (exempt-отличия, INV-GOLDEN-GATE, будущий SUPERSEDED)
2 ERROR
есть ошибки-находки, либо ABORT записи (git_guard/verify)
3 REVALIDATE
только propagate/revalidate: сходимость не подтвердилась (у propagate — уже после авто-отката)
5 INTERNAL
прервано (Ctrl-C)
6 CONFLICT
капкан: канарейка capture упала (vault не закоммичен) / конфликт install (target не тронут). Никогда «наполовину»

7 · Термины

инвариант (invariant)
правило, которое обязано выполняться всегда; нарушение = находка (Finding)
канарейка (canary)
маленькая проверка-сторож, которая падает первой и громко
гейт (gate)
ворота: проверка, провал которой блокирует следующий шаг
мета-тест / meta-proof
проверка самой проверки: «сломай нарочно → RED, почини → GREEN»; ловит канарейку-тавтологию
fail-open / fail-closed
что делать, если сторож сам сломан: пропустить (open) или заблокировать (closed)
