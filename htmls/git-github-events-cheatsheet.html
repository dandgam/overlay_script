git hooks → GitHub workflows → деплой

Все точки-события от первого касания файлов до прода. Везде одна парадигма «событие → действие». pre- = гейт, срабатывает до и может заблокировать (exit≠0 останавливает). post- = обсервер, срабатывает после и только реагирует.

асимметрия гейтов

Слева гейтов много — это pre-* хуки на твоей машине. Справа гейт по сути один — branch protection. Почти все GitHub-события — обсерверы: они запускают раннер, а блокировку даёт exit-код внутри него или защита ветки, а не само событие.

третий этаж той же парадигмы

Claude Code hooks — PreToolUse / PostToolUse / Stop / SubagentStop — это события агента, отдельная система от git-хуков и workflow. Та же логика «событие → действие», но git-хук ловит git-операцию, а Claude-хук — действие агента. Не смешивать.
