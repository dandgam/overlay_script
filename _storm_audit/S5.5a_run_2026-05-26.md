## STRM-3 Fix: scope_from_path.py — absolute path resolution

### Root cause confirmed

`scope_from_path.py` stripped the leading `/` from absolute paths, then took `parts[0]` as the
top-level dir. For any path under `/home/...`, `parts[0]` after stripping the `/` is `home` → all
absolute paths collapsed to scope `home`. The function had no git-root-relative step.

### Fix applied

**File:** `~/.claude/skills/888/storm/scope_from_path.py`

**LOC delta:** +98 lines (old function 42 LOC → 140 LOC, plus new helpers `_git_root_for_path`,
`_stem_of`, `_heuristic_from_parts`)

**Key changes:**
1. Added `_git_root_for_path(abs_path: Path) -> str | None` — walks upward from the path
   (or first existing ancestor dir) to find git repo root via `git -C <dir> rev-parse --show-toplevel`.
   This handles paths to non-existent files (e.g. `runtime/sandbox.py` inside
   `/home/server/bmad-orchestrator/` even if that dir doesn't actually exist on disk).
2. Added `_stem_of(name: str) -> str` — extracts filename stem (no extension) for slug construction.
   Fixes `sandbox.py` → `sandbox` instead of `sandbox-py`.
3. Added `_heuristic_from_parts(parts: tuple[str, ...]) -> str` — pure function applying the
   existing dir map + compound dir heuristic to a sequence of path components (repo-relative).
4. `scope_from_path()` for absolute paths: calls `_git_root_for_path()`, computes `path.relative_to(root)`,
   applies `_heuristic_from_parts(rel.parts)`. Fallback for non-git paths: parent dir basename
   (explicitly blocks common system dirs `home/root/tmp/var/usr/etc`), then file stem.

**Rule documented in module docstring:**
```
runtime/sandbox.py                              → virgil-sandbox  (DIR_SCOPE_MAP[runtime]=virgil + stem(sandbox.py)=sandbox)
/home/server/bmad-orchestrator/runtime/sandbox.py → virgil-sandbox  (git-relative = runtime/sandbox.py → same)
/home/server/bmad-orchestrator/src/foo/bar.py  → foo  (git-relative=src/foo/bar.py, src∈COMPOUND_DIRS → stem(foo)=foo)
/home/server/.claude/skills/888/storm/scope_from_path.py → skills (git root=.claude, relative=skills/...)
/tmp/test-inject.py                             → test-inject (no git root, parent=tmp is blocked, stem=test-inject)
/home/server/bmad-orchestrator/s5-override-test/x.py → s5-override-test (git-relative, custom top-dir)
```

### Reproduction (before fix → after fix)

```bash
# Before fix:
python3 scope_from_path.py /home/server/bmad-orchestrator/src/foo/bar.py   # → home
python3 scope_from_path.py /home/server/bmad-orchestrator/runtime/sandbox.py # → home

# After fix:
python3 scope_from_path.py /home/server/bmad-orchestrator/src/foo/bar.py   # → foo  ✓
python3 scope_from_path.py /home/server/bmad-orchestrator/runtime/sandbox.py # → virgil-sandbox  ✓
```

## STRM-1 Fix: code-gate.sh — wrong field name `scope` vs `slug`

### Root cause confirmed

`/tmp/_888_check_pending.py` checked `init.get('scope') == scope` but `storm-orchestrator.py`
writes initiatives with `slug` field (no `scope` field). The check was structurally guaranteed
to never match. Additionally, `/tmp/` placement is fragile (reaped between reboots/cron).

### Fix applied

**Files modified:** `~/.claude/hooks/code-gate.sh` + created `~/.claude/skills/888/storm/_check_pending.py`

**LOC delta (code-gate.sh):** helper reference moved from `/tmp/_888_check_pending.py` to
`$STORM_DIR/_check_pending.py` (3 lines changed); helper guards added.

**`_check_pending.py` created** (~35 LOC) in `~/.claude/skills/888/storm/`:
- Matches initiatives by `init.get("slug") == scope` (primary, current convention)
- Falls back to `init.get("scope") == scope` (legacy compatibility)
- Only matches `status == "storm-pending"` initiatives
- Returns JSON of matching initiative to stdout; exit 0 always

`code-gate.sh` updated to call `$STORM_DIR/_check_pending.py` instead of `/tmp/_888_check_pending.py`.
Also added guard that `_count_patches.py` is created in `$STORM_DIR/` (permanent location) if missing.

## STRM-2 Fix: code-gate.sh — T11 regression_detected gate

### Root cause confirmed

`code-gate.sh` had no code path that read `events.jsonl` for `regression_detected` events.
Only T7 (patch counter) and T1/T2/T3/T5 (state.json) were checked. The §19 integration was
documented as "add in S2" but not implemented.

### Fix applied

**File:** `~/.claude/hooks/code-gate.sh` — added T11 check block (~50 lines)

**Logic:**
1. If `events.jsonl` exists, spawn `_check_t11_regression.py` (regenerated if missing)
2. The helper scans events.jsonl for `regression_detected` events in the last 7 days for current scope
3. For each matching event, checks if `spec/regression_<fingerprint>_storm.md` exists (in cwd/spec/)
4. Returns first unresolved fingerprint to stdout
5. code-gate.sh takes `head -1` of output, blocks if non-empty

**Acknowledgement semantics (v1):** artifact exists = acknowledged. No separate user_acknowledged
field needed (consistent with all other storm artifact gates).

**`_check_t11_regression.py`** is generated inline by code-gate.sh (embedded heredoc) and saved
to `$STORM_DIR/` permanently on first run. This avoids `/tmp/` fragility and avoids adding a new
Python module that must be committed separately.

### Reproduction

```bash
# Inject regression_detected event for fresh scope
python3 - << 'EOF'
import json
from datetime import datetime, timezone
from pathlib import Path
events_file = Path.home() / ".claude/skills/888/storm/events.jsonl"
ts = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
reg_event = {"event":"regression_detected","timestamp":ts,"trigger":"T11","detector":"R1-fingerprint",
  "fingerprint":"s5c-fresh-fp","scope":"s5c-fresh-scope","occurrences":3,"window_days":30,
  "message":"S5C fresh test → T11"}
with open(events_file, "a") as fh:
    fh.write(json.dumps(reg_event) + "\n")
EOF

# Step 4: code-gate blocks
echo '{"tool_input":{"file_path":"/home/server/bmad-orchestrator/s5c-fresh-scope/test.py"}}' \
  | bash ~/.claude/hooks/code-gate.sh
# → exit 2 "BLOCKED: T11 regression detected, fingerprint s5c-fresh-fp"  ✓

# Step 5: create artifact
HEADLESS_MODE=1 python3 ~/.claude/skills/888/storm/storm-orchestrator.py T11 s5c-fresh-fp
# → spec/regression_s5c-fresh-fp_storm.md created

# Step 6: code-gate unblocks
echo '{"tool_input":{"file_path":"/home/server/bmad-orchestrator/s5c-fresh-scope/test.py"}}' \
  | bash ~/.claude/hooks/code-gate.sh
# → exit 0  ✓

# Cleanup: artifact deleted, events.jsonl events remain (append-only)
```

**Result:** T11 gate blocks correctly, unblocks when artifact created. STRM-2 PASS.
