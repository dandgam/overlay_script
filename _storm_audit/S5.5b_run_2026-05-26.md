### Cascade behavior change (§18 step 3)

- `STORM_LLM_BACKEND=stub` (default): unchanged — returns `optional_pool[:1]` + stderr warning.
- `STORM_LLM_BACKEND=claude-p`: one `claude -p` call with a structured prompt + JSON-output
  contract. Response parsed (tolerant — handles fenced blocks + stray preamble), validated
  against pool, capped at 2 picks. On any failure → fallback to stub behavior.

### Per-method change

- `_method_section()` accepts `trigger_id` + `backend`. With `claude-p`, invokes
  `_llm_method_findings(mid, trigger_id, slug)` which makes one `claude -p` call per method
  and substitutes the markdown body. On failure → placeholder kept.

### Event schema additions (events.jsonl)

| Event | Fired when | Payload |
|---|---|---|
| `llm_call` | success | backend, caller, trigger_id, slug, prompt_chars, response_chars, exit_code, duration_ms |
| `llm_call_failed` | non-zero exit / OSError | + error / stderr_excerpt |
| `llm_call_timeout` | `subprocess.TimeoutExpired` | + timeout_seconds |
| `llm_response_empty` | exit 0, empty stdout | — |
| `llm_parse_failed` | judge response not JSON | + raw_excerpt (≤300 chars) |
| `llm_backend_unavailable` | `shutil.which("claude")` → None | logged once per storm |
| `llm_budget_exceeded` | wall-clock cap hit | logged once per storm |

`storm_method_selection` event extended with `llm_judge_backend` + `llm_judge_rationale`.

## 9. Open findings / new observations

1. **Q-260526-STRM-4 is now CLOSED** at the orchestrator layer. The stub is preserved as
   default + fallback.
2. **`INSUFFICIENT_CONTEXT` is a feature, not a bug.** Generic-slug storms produce
   `INSUFFICIENT_CONTEXT` for context-hungry methods (Critique, First Principles) while
   process-level methods (Meta-Prompting, Tree of Thoughts, Red Team) still produce
   actionable content. This is the right behavior — prevents fake-confidence output.
3. **Context enrichment opportunity:** the per-method prompt currently passes only
   `slug + trigger`. A future enhancement could pass scenario.md `detection_keywords` and
   the tail of `events.jsonl` (per spec §18 prompt template) to ground methods better. Out
   of scope for S5.5b; track as a separate follow-up.
4. **Pre-existing ruff warnings** (F401 on `STATE_FILE`/`STORM_DIR`, I001 import sort) are
   not addressed — they predate S5.5b and lie outside its scope. `S603/S607` (subprocess
   security) suppressed inline with focused `# noqa`.
5. **Module-level `_llm_state`** is reset at the top of `run()` — each storm gets a fresh
   budget + fresh one-time-warning state. Safe under repeated invocation within a single
   Python process (e.g. tests).
