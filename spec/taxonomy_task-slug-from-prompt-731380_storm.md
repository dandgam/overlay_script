**Component grounded:** `~/.claude/skills/888/storm/task_slug_from_prompt.py` · sole runtime caller `~/.claude/hooks/intent-detector.sh:71`.

## Findings (failure modes of the component + the proposed fix)

- **FM1 — Case-blind comparison re-leaks the bug.** Candidates from `kws` keep original case; `_STOPWORDS` is lowercase-only. If the fix writes `kw not in _STOPWORDS` instead of `kw.lower() not in _STOPWORDS`, sentence-initial `"Fix the bug…"` still yields `fix-<hash>`. Most likely implementation defect.

- **FM2 — Slug is a JOIN KEY; changing derivation is a migration, not a cosmetic edit.** The same value feeds `_check_active.py init` (state.json `active_task`) **and** `storm-orchestrator.py --print-artifact-path` → `spec/taxonomy_<slug>_storm.md` (intent-detector.sh:71→76→81). Land the fix mid-task and the gate recomputes a *new* slug while the pending artifact sits under the *old* slug → permanent `code_gate_blocked` deadlock. This is the producer≠consumer seam from [[feedback_integration_seam_blind_spot]] / `b5_soak_double_seam`. **Blast radius of the fix > severity of the bug.**

- **FM3 — Filtering deletes the only hint → generic regression.** `"fix the bug"` → all kws filtered → `task-<hash6>` (acceptable). But `"обнови add конфиг"` → `kws=["add"]` → currently `add-<hash>`, post-fix `task-<hash>`. When the sole ASCII token is a stopword, a weak hint becomes no hint. Trade-off must be deliberate, not accidental.

- **FM4 — Over-broad fix corrupts the Q-ID branch.** L40–44 derives from the human-curated Q-ID name (e.g. `Q-…-FIX-SLUG` → `…-fix-slug`) — a *stable machine-name contract*. If stopword stripping is "consistently" applied there too, writer/reader slugs diverge again (same deadlock class). The Q-ID path must stay byte-for-byte unchanged.

- **FM5 — Substring stripping mangles real words.** If implemented as `re.sub(r'\bfix\b','',prompt)` then re-tokenize, partial/edge matches risk `"prefix"/"suffix"/"hotfix"`. Safe shape = filter the already-tokenized `kws` list token-by-token; never regex the raw prompt.

- **FM6 — Bug is informativeness-only (LOW), not correctness.** `h = sha256(full prompt)` (L45) → uniqueness is independent of the lead keyword. Two prompts differing only in stopwords already get distinct hashes. Skipping the fix causes zero collisions — confirming the real danger lives in FM2, not in leaving the bug.

- **FM7 — No test pins the contract.** `test_storm_task_context.py` exists but (per the bug) has no case asserting stopword-leading prompts pick the next topical keyword, all-stopword falls back, and the Q-ID branch is untouched → a later refactor silently re-breeds this.
