### #35 Failure Mode Analysis (FMA)

## FMA — Failure Mode Analysis: `888-wave6-t9forced` (T7 Bug Fix Taxonomy)

Scope analyzed: forced-T9 stuck-detector — `t9-counter.sh` (Stop hook) → `_t9_streak.py` (signal) → `_set_pending.py` (producer) → `code-gate.sh`/`_check_pending.py` (consumer). Grounded in actual source, not the design doc.

### Findings (per-component failure modes)

- **F1 — Reason-migration defeats the streak (signal, P0).** `_t9_streak.compute` counts a tail run of the *exact same* `reason` string (`_t9_streak.py:105` — any change → `streak=1`). But `code-gate.sh` emits **6 distinct reasons** for the same stuck scope: `decider_storm_pending`, `decider_placeholder`, `storm_pending`, `storm_mandatory_incomplete`, `T7_patch_count_exceeded`, `T11_regression_unresolved`. A genuinely-stuck agent naturally *migrates* between them (blocked → creates a placeholder artifact → now `decider_placeholder` → fills partial → `storm_mandatory_incomplete`). Each migration resets the counter → **streak never reaches 3 → forced-T9 never fires.** The signal assumes monotone reason; the gate produces a reason *gradient*. Classic false-negative seam.

- **F2 — Most-recent-scope masking (signal, P1).** Only the single scope of the *last* block is evaluated (`_t9_streak.py:84-87`). `events.jsonl` is global/shared. If stuck scope A (3×) is followed by one block on scope B, candidate=B, streak=1 → A's escalation is shadowed every Stop until B goes quiet. Interleaved work permanently masks a stuck scope.

- **F3 — Stale idempotency marker = permanent disarm (state, P1).** `t9_escalations[scope]` is cleared *only* when that scope is the candidate **and** `streak<2` (`t9-counter.sh:45-47`). After a forced-T9 fires, marker=3. If the scope later gets unstuck without a Stop ever observing `streak<2` for it (window slid, or another scope is candidate), the marker sticks at 3. Next genuine stuck episode: `PREV(3) < T9_LIMIT(3)` is **false** → forced-STOP **never fires again for that scope, ever.** One-shot net that disarms itself.

- **F4 — Override escape-hatch silently resets the counter (state, P1).** `manual_override` events are treated as a hard reset (`_t9_streak.py:72-75, 98-102`). The gate's documented last-resort `echo "<reason>" > /tmp/.888_override_<scope>` emits exactly that event. An agent can grind past T9 indefinitely by overriding **once per 2 blocks** — the very pattern-symptom-patching the mechanism exists to stop.

- **F5 — Producer↔orchestrator artifact-path seam (producer/consumer, P0 risk).** `t9-counter.sh:53` writes `required_artifact = spec/t9_${SCOPE}_storm.md`. The user is told to run `storm-orchestrator.py T9 <scope>` (`:59`). If the orchestrator writes its T9 artifact to a *different* conventional filename, the per-scope gate (`_check_pending` → artifact existence/non-placeholder) never sees satisfaction → **eternal block / deadlock** — the exact double-seam class already burned twice in this project (`[[project_milestone_b5_soak_double_seam_2026-06-02]]`: decider `t7_<slug>` vs orchestrator `taxonomy_<slug>`). **Unverified here** — must be checked before enabling.

- **F6 — Per-file scope dilution (scope derivation, P2).** `SCOPE` is derived per *file path* (`code-gate.sh:50-62`, `scope_from_path.py`), not per *task*. An agent stuck on one logical bug but touching files that map to different scopes spreads blocks across scopes; no single scope reaches 3. Granularity mismatch between "stuck on a problem" and "stuck on a file-scope."

- **F7 — Stop-hook delivery + fail-open dependency chain (delivery, P2).** Evaluated only on agent Stop; fail-OPEN on every dependency (`t9-counter.sh:28-33`: flag off, missing `jq`, missing events/streak file, python error → `exit 0`). Session crash/SIGKILL/`/clear`, or a degraded sandbox without `jq`/`python3`, silently disarms the net with no audit of the disarm.

### Recommended actions

1. **F1 (blocker):** count the streak on a **stable key** = `(scope, trigger)` or a reason-*class* (collapse all `decider_*`/`storm_*` block reasons for the same scope into one "still-blocked-on-storm" class), not the raw reason string. Or: count consecutive `code_gate_blocked` for a scope *regardless of reason*, resetting only on `manual_override`/`storm_completed`. Add a test where reason migrates `decider_storm_pending → decider_placeholder → storm_mandatory_incomplete` and assert streak reaches 3.
2. **F5 (blocker, pre-enable):** verify `storm-orchestrator.py T9 <scope>` writes to **exactly** `spec/t9_<scope>_storm.md` (the path `_set_pending` records), or make the producer read the orchestrator's canonical path from a single source. Add a meta-proof: forced-T9 fires → run orchestrator → assert gate unblocks (the §E contract-test pattern from B5).
3. **F3:** clear the marker on `storm_completed`/`manual_override` for the scope (event-driven), not only on the `streak<2` Stop path; or store marker with the block-fingerprint so a *new* stuck episode re-arms.
4. **F4:** don't reset streak on `manual_override` — instead count overrides and escalate *faster* (override-while-stuck is a stronger stuck signal, not a weaker one).
5. **F2:** evaluate *all* stuck scopes in-window each Stop, not just the last-blocked one.
6. **F7:** on fail-open due to missing `jq`/`python3`, emit a loud `t9_disarmed` audit event (consistent with the sandbox `NoSandbox` loud-warning convention in `CLAUDE.md` §Critical Boundaries).

**Note:** Mechanism is dormant (`BMAD_888_T9_FORCED` default off). F1 and F5 must be closed **before** the canary flip, else the first real-pilot enablement reproduces the deferred-canary→future-bug pattern (`[[feedback_canary_gap_root_of_breeding]]`).
