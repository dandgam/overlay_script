### #35 Failure Mode Analysis (FMA)

## FMA #35 — Q-260526-DGSB «fail-closed sibling sweep»

**Verdict up front:** на диске сейчас фикс применён ТОЛЬКО к `merge-guard.sh`. Два из трёх названных siblings (`code-gate.sh:7`, `audit-trail.sh:9`) **всё ещё `exit 0` на missing jq**. Тот самый bypass-класс, ради которого открыт Q, остаётся живым в primary Layer-1 гейте. Это [[feedback_integration_seam_blind_spot]] в чистом виде.

### Failure modes (по компонентам)

- **F1 [CRITICAL] — sibling sweep НЕ завершён, primary guard открыт.** `code-gate.sh:7` = `command -v jq … || { … exit 0; }`. Это главный PreToolUse-гейт (settings.json:124), блокирующий Edit/Write без storm-артефакта. `apt remove jq` → code-gate молча пропускает ВСЕ правки. Фикс закрыл merge-guard (редкий путь — только merge-команды), но оставил открытым самый горячий путь. Задача декларирует закрытие 3 siblings, факт — 1/3.

- **F2 [HIGH] — слепое копирование `exit 2` в `audit-trail.sh` семантически неверно.** audit-trail зарегистрирован как **Stop**-хук (settings.json:256/266), не PreToolUse. Stop-hook `exit 2` НЕ блокирует tool-action (action уже произошёл) — он блокирует *остановку агента* и форсит продолжение → при отсутствии jq агент не сможет завершиться (hang/loop), self-DoS. «Fail-closed» для observability-хука ≠ `exit 2`; нужен jq-free путь логирования (`printf`) + escalation. Если фикс «причешет» audit-trail под шаблон merge-guard — внесём новый дефект.

- **F3 [HIGH] — PATH-shadow обходит фикс целиком.** `command -v jq` проходит, если на PATH есть *любой* `jq`. Атакующему не нужен `apt remove`; достаточно положить фейковый `jq` (скрипт, печатающий пустой/безобидный JSON) в начало PATH. Тогда fail-closed не срабатывает, а `jq -r … 2>/dev/null` отдаёт пустую строку → `COMMAND=""` → `exit 0` (fail-open). Фикс защищает от *отсутствия*, не от *подмены*.

- **F4 [HIGH] — missing-jq не единственный fail-open-вектор.** Везде `jq -r … 2>/dev/null` глотает ошибки парсинга: jq present-but-broken (битый бинарь, несовместимая версия), усечённый stdin, malformed INPUT → пустой результат → exit 0. fail-closed-on-missing — необходимо, но не достаточно; контракт должен быть «не смог достоверно распарсить → block», а не «нет бинаря → block».

- **F5 [MEDIUM] — producer-сторона молча разоружается.** `intent-detector.sh:9` и `patch-counter.sh:9` тоже `exit 0` на missing jq. Без jq intent-detector не ставит `active_task`, patch-counter не инкрементит T7 → decider не армится, taxonomy не требуется. Даже с почINENным code-gate энфорсить будет нечего (нет active_task). Удаление jq разоружает цепочку целиком, не один гейт.

- **F6 [MEDIUM] — over-broad fail-closed = availability-инцидент.** code-gate — PreToolUse на Edit/Write. `exit 2` на missing jq заблокирует ВСЕ правки на хосте, где jq легитимно отсутствует (свежий worktree, CI-sandbox, **bwrap-песочница воркера без jq**). Это «кирпичит» агента так же, как NoSandbox-сценарий (CLAUDE.md §Critical Boundaries). Нужно различать «jq отсутствует в этой среде» (loud audit warning) и «jq убран атакующим».

- **F7 [MEDIUM] — нет единого источника → дрейф рецидивирует.** `command -v jq` переписан независимо в 10+ хуках, теперь с ДВУМЯ политиками (exit 0 vs exit 2). Это и есть корневой баг: per-file фикс расходится. Дефект уже рецидивировал (DGEX→DGSB). Следующий новый хук скопирует политику соседа наугад.

### Risks
- **R1:** «victory declared» на неполном sweep — Q закроют, а primary bypass (F1) останется → ложное чувство закрытия, будущая инициатива (паттерн [[feedback_canary_gap_root_of_breeding]]).
- **R2:** фикс audit-trail внесёт hang/self-DoS (F2).
- **R3:** даже полный sweep не закрывает PATH-shadow/broken-jq (F3/F4) — security-театр.
- **R4:** fail-closed без env-discrimination ломает воркеров в песочнице (F6).

### Recommended actions
1. **Закрыть F1 немедленно** — `code-gate.sh:7` на fail-closed (`exit 2` + audit-event), это primary guard; без него Q не закрыт.
2. **audit-trail (F2):** НЕ `exit 2`. jq-free лог (`printf` JSON) + пометка `degraded`; не блокировать Stop. Зафиксировать в taxonomy что «fail-closed» зависит от типа хука (PreToolUse=block / Stop=log-and-flag).
3. **Единый источник (F7):** вынести `lib/_require_jq.sh`, source во всех security-хуках; политика block/skip — параметром. + **тест-инвариант**: «каждый PreToolUse-guard на missing jq даёт exit 2» (gate-beats-self-review, иначе sweep снова разойдётся).
4. **F3/F4:** контракт «не распарсил достоверно → block» (проверять не наличие бинаря, а успех парсинга + непустой ожидаемый ключ); опционально pin абсолютного пути jq или хеш-чек.
5. **F6:** env-флаг (напр. `BMAD_888_REQUIRE_JQ`) — в песочнице/CI allowlist «jq legitimately absent» = loud warning, не block; на основном хосте = block.
6. **Канарейка:** реальный прогон `PATH-shadow fake-jq` + `jq removed` против ВСЕХ 4 гейтов, не unit-mock — иначе F1-класс снова просочится мимо теста (как в double-seam soak).

### Риски

- Артефакт `spec/taxonomy_260526-dgsb_storm.md` наполнится мета-рассуждениями, не таксономией DGEX-бага → gate пропустит болванку как «заполнено».

2. **Проверить seam:** method-промпт должен брать тело задачи у того же писателя, что и `--print-artifact-path` (single source), а не из предыдущего active_task — иначе recursion method-over-method повторится.
