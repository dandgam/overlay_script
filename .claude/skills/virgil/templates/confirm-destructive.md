# confirm-destructive.md

> Двухшаговое подтверждение для опасных операций. Заменяет упрощённый placeholder из Session 1.
> Читать **только** когда пользователь выбрал destructive-опцию в одном из sub-меню.

## Зачем два шага

`AskUserQuestion` — кнопочное подтверждение. Один клик может случайно сделать тот кто промахнулся мышкой. Для необратимых операций добавляем **второй шаг — ввод фразы текстом**. Случайно напечатать «STOP HARD» большими буквами уже не получится.

Защищаемые операции:

| Операция | Фраза для подтверждения | Что произойдёт |
|---|---|---|
| `stop --hard` | `STOP HARD` | Все работники убиваются немедленно, несохранённая работа теряется |
| `stop --graceful` | `STOP` | Проход останавливается после текущих задач (мягче, но необратимо) |
| `policy-rollback <slug> <id>` | `ROLLBACK POLICY` | Policy проекта откатывается к бэкапу |
| `self-learning rollback <id>` | `ROLLBACK LEARNING` | Откат правки policy из self-learning |
| `skill-update --apply` (когда уже есть diff с конфликтами) | `APPLY SKILL UPDATE` | Перезапись `skills/upstream/` |

## Шаблон двухшагового подтверждения

### Шаг 1 — предупреждение через `AskUserQuestion`

Покажи последствия простыми словами и дай выйти:

- **question:** «⚠ Необратимое действие — `<название операции>`. Подтверждаешь?»
- **header:** «⚠ Подтверждение»
- **options (2):**

  1. **label:** «⛔ Отменить» (рекомендуется)
     **description:** «Ничего не произойдёт. Вернусь в предыдущее меню»

  2. **label:** «➡ Продолжить — попрошу ввести фразу»
     **description:** «Перейду к шагу 2: попрошу напечатать подтверждение текстом»

**В тексте `question` или в самом сообщении перед `AskUserQuestion`** — описать последствия для конкретной операции (см. таблицу выше).

### Шаг 2 — ввод фразы текстом

Если выбрано «Продолжить» — отправь обычное сообщение в чат:

> «Чтобы подтвердить, напечатай **точно** эту фразу (заглавными): `<phrase>`
>
> Любой другой текст отменит операцию.»

`<phrase>` — из таблицы выше. **Точное совпадение** (case-sensitive). Никаких вариаций.

**Логика проверки:**
- Если ввод === ожидаемая фраза → выполнить `Bash` команду.
- Если что-то другое → ответить «❌ Подтверждение не совпало (получено: `<что ввёл>`). Отменяю операцию.» и **не выполнять**.
- Не давать вторую попытку — если пользователь промахнулся, пусть начнёт операцию заново через меню. Это намеренно неудобно — защита от автоматизма.

## Примеры

### Пример 1 — `stop --hard`

Пользователь: 🚀 Запустить → ⏹ Остановить → 💥 Экстренный стоп

**Шаг 1:**

> ⚠ **Внимание — экстренный стоп.** Последствия:
> • Все работники убиваются немедленно (SIGKILL)
> • Несохранённая работа за последний час-два **теряется безвозвратно**
> • Проход помечается как aborted в state.db
>
> Используй только если оркестратор завис и не реагирует на обычный стоп.

`AskUserQuestion`: «⛔ Отменить» / «➡ Продолжить — попрошу ввести фразу»

**Шаг 2** (если «Продолжить»):

> Чтобы подтвердить, напечатай **точно** заглавными: `STOP HARD`
>
> Любой другой текст отменит операцию.

Пользователь: `STOP HARD` → `Bash`: `/home/server/bmad-orchestrator/.venv/bin/bmad-orchestrator stop --hard`. Foreground.

Если ввёл `stop hard` (lowercase) или что-то ещё → «❌ Не совпало, отменяю».

### Пример 2 — `policy-rollback`

Пользователь: ⚙️ Настройка → 📜 Policy → ↩️ Откатить правку

После того как уже спросили slug проекта и id правки:

**Шаг 1:**

> ⚠ **Откат policy проекта `<slug>`.** Последствия:
> • Файл policy откатится к состоянию **до правки `<id>`**
> • Все изменения внесённые этой правкой пропадут
> • Backup останется (`.yaml.bak-<id>`) — можно откатить откат вручную

`AskUserQuestion`: «⛔ Отменить» / «➡ Продолжить»

**Шаг 2:**

> Чтобы подтвердить, напечатай заглавными: `ROLLBACK POLICY`

При успехе → `Bash`: `/home/server/bmad-orchestrator/.venv/bin/bmad-orchestrator policy-rollback <slug> <id>`.

### Пример 3 — `self-learning rollback`

Пользователь: 🧪 Качество → 🧬 Самообучение → ↩️ Откатить правку

После того как спросили id правки:

**Шаг 1:** аналогично, описать что policy вернётся к предыдущему состоянию.

`AskUserQuestion`: «⛔ Отменить» / «➡ Продолжить»

**Шаг 2:**

> Напечатай заглавными: `ROLLBACK LEARNING`

При успехе → `Bash`: `/home/server/bmad-orchestrator/.venv/bin/bmad-orchestrator self-learning rollback <id>`.

## Что НЕ требует двухшагового confirm

| Операция | Почему хватает одного шага |
|---|---|
| `pause` / `resume` | Обратимы — работники продолжат с того же места |
| `init <path>` | Аддитивно — добавляет проект в реестр, ничего не удаляет |
| `model set <role> <value>` без `--save` | Только на сессию, не пишет в файл |
| `model save` | Перезаписывает YAML с текущей раскладкой — можно вернуть руками |
| `policy-apply <slug>` без `--auto-apply` | Спрашивает каждую правку отдельно |
| `skill-update` без `--apply` | Сухой прогон — ничего не пишет |

Для этих — один `AskUserQuestion` «Да / Отмена» достаточно.

## Edge cases

- **Пользователь ввёл фразу с лишним пробелом** (`STOP HARD ` или ` STOP HARD`) — strip whitespace перед сравнением. Это «промах», не злоупотребление.
- **Пользователь ввёл фразу маленькими** (`stop hard`) — НЕ принимать. Точное case-sensitive совпадение. Заглавные = намеренное действие.
- **Пользователь ввёл `да` / `yes` / `подтверждаю`** — НЕ принимать. Только точная фраза из таблицы.
- **Пользователь хочет отменить уже на шаге 2** — любой не-совпадающий ввод = отмена. Дополнительной кнопки «отмена» не нужно.
