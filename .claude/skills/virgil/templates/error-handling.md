# error-handling.md

> Что делать когда `Bash` команда вернула exit code != 0.
> Читать когда CLI упал, перед тем как ответить пользователю.

## Общий принцип

Skill **не пытается** автоматически «починить» ошибку — пользователь должен видеть что случилось и сам решать. Цель этого файла — превратить технический stderr в **понятное русское объяснение + конкретное предложение что делать дальше**.

## Алгоритм разбора

1. Прочитать stderr (последние ~20 строк — самое релевантное обычно внизу).
2. Найти **сигнатуру** в таблице ниже — характерное сообщение / класс исключения / pattern.
3. Если совпало → ответить **по шаблону из таблицы** (русский + suggestion).
4. Если ничего не совпало → показать stderr дословно + общий fallback (см. ниже).

## Таблица сигнатур

### Проблемы с проектом

| Pattern в stderr | Что произошло (русский) | Что предложить |
|---|---|---|
| `BMadProjectNotFound`, `project '...' not registered`, `ProjectRegistryError` | Проект не зарегистрирован в реестре | «Сначала зарегистрируй проект: `/virgil` → ⚙️ Настройка → 📁 Проекты → ➕ Зарегистрировать (или укажи правильный slug). Текущий список: `/virgil` → ⚙️ Настройка → 📁 Проекты → 📋 Список»  |
| `path does not exist`, `FileNotFoundError: ...` (при init) | Указанный путь не существует на диске | «Папка по этому пути не найдена. Проверь что путь абсолютный и существует (`ls -la <путь>`). Попробуй заново через `/virgil` → ⚙️ Настройка → 📁 Проекты → ➕ Зарегистрировать.» |
| `path is not absolute` | Передан относительный путь | «Нужен **абсолютный** путь (начинается с `/`). Например: `/home/server/antares`, а не `./antares` или `~/antares`.» |
| Doctor проверка: `fail` | Проект найден, но что-то с ним не так | «Health-check не прошёл. Посмотри детали в выводе выше — там видно что именно сломано (отсутствует `_bmad/`, нет `epics.md`, etc).» |

### Проблемы с проходом (wave)

| Pattern | Объяснение | Предложение |
|---|---|---|
| `WaveAlreadyRunning`, `session already active` | Этот проход уже запущен | «Проход уже идёт. Посмотреть состояние: `/virgil` → 📊 Статус → 📈 Что сейчас работает. Остановить: `/virgil` → 🚀 Запустить → ⏹ Остановить.» |
| `WaveNotFound`, `no session for wave X` | Такого прохода нет в state.db | «Прохода с таким номером не было. Проверь правильность номера (формат `1a`, `2b`...) или запусти новый: `/virgil` → 🚀 Запустить → 🆕 Новый проход.» |
| `SprintStatusMissingError`, `sprint-status.yaml not found` | У проекта нет планового файла со списком задач | «У проекта нет `sprint-status.yaml` — нужно сначала прогнать BMad Phase 1-3 (планирование). Это вне scope Virgil — делается отдельно через BMad-Method skills.» |
| `BudgetExceeded`, `halt threshold breached` | Превышен порог бюджета (дневной или wave-scope) | «Превышен бюджет. Детали: `/virgil` → 📊 Статус → 💰 Сколько денег потрачено. Можно увеличить лимит (`--max-spend-usd N` при запуске) или подождать до сброса дневного счётчика.» |

### Проблемы с работниками

| Pattern | Объяснение | Предложение |
|---|---|---|
| `WorkerNotFound`, `no worker '...' in wave` | Указанного работника нет в текущем проходе | «Такого работника нет. Имена работников — в `/virgil` → 📊 Статус → 📈 Что сейчас работает (колонка `worker`).» |
| `worker_halt_file detected` | Работник остановлен halt-файлом | «Работник остановлен — посмотри причину в его логах: `/virgil` → 📊 Статус → 📜 Логи работника.» |
| `worktree already exists`, `worktree path locked` | Worktree от прошлого прохода не убран | «Остался worktree от предыдущего прохода. Это известная проблема (см. backlog runner_reused_worktree_cleanup). Workaround: убрать вручную `git worktree remove <path>` в target проекте.» |

### Проблемы с CLI / системой

| Pattern | Объяснение | Предложение |
|---|---|---|
| `command not found`, exit 127 | `bmad-orchestrator` не найден | «CLI не на PATH. Проверь полный путь: `/home/server/bmad-orchestrator/.venv/bin/bmad-orchestrator` (см. `templates/command-bridge.md` раздел 0). Если venv удалён — пересоздать: `cd /home/server/bmad-orchestrator && python -m venv .venv && .venv/bin/pip install -e .`» |
| `ModuleNotFoundError: No module named 'bmad_orchestrator'` | Пакет не установлен в venv | «Пакет не установлен. Запусти: `cd /home/server/bmad-orchestrator && .venv/bin/pip install -e .`» |
| `Permission denied` (на запись в `.venv/`, `state.db`) | Нет прав на файлы | «Нет прав на запись. Проверь владельца файла (`ls -la <path>`) или права (`stat <path>`).» |
| `OSError: [Errno 28] No space left on device` | Кончилось место на диске | «Кончилось место на диске. Проверь: `df -h /home`. Освободи место (логи в `.claude/`, старые worktree копии) или подключи доп-том.» |
| `sqlite3.OperationalError: database is locked` | state.db залочен другим процессом | «State.db заблокирована. Подожди 10 секунд и попробуй снова — другой процесс пишет. Если не отпускает — проверь нет ли зависшего `bmad-orchestrator` процесса.» |

### Проблемы с policy / self-learning

| Pattern | Объяснение | Предложение |
|---|---|---|
| `policy yaml not found` | YAML policy отсутствует | «Файл policy не найден. Проверь путь (по умолчанию `config/elicitation-policy.yaml`). Создать: см. пример в `examples/elicitation-policy.example.yaml`.» |
| `invalid YAML: ...` | Битый YAML | «Файл policy с синтаксической ошибкой. Подсказка от парсера: `<деталь из stderr>`. Исправь YAML (отступы, кавычки) и попробуй снова.» |
| `policy proposal not found by id` | Передан несуществующий id для отката | «id правки не найден. Список применённых правок — в audit-логе self-learning. Сначала глянь `/virgil` → 🧪 Качество → 🧬 Самообучение → 📚 Чему научился.» |
| `policy-proposals.yaml not found for slug` | У проекта нет накопленных предложений | «У проекта пока нет предложенных правок. Нужно сначала запустить self-learning: `/virgil` → 🧪 Качество → 🧬 Самообучение → ▶️ Запустить обучение сейчас.» |

### Telegram-бот

| Pattern | Объяснение | Предложение |
|---|---|---|
| `Connection refused`, `bot not running` | Бот не запущен | «Telegram-бот не запущен. Это команда для другого scope — запускается отдельно (см. CLI `bmad-orchestrator bot-start`).» |

## Fallback — ничего не совпало

Если pattern не нашёлся в таблицах выше:

> ❌ **Команда завершилась с ошибкой** (exit code: `<N>`).
>
> Что вывел оркестратор:
> ```
> <последние 15-20 строк stderr>
> ```
>
> Не знаю эту ошибку по сигнатуре. Если нужна помощь с разбором — скажи, посмотрим вместе. Можно также проверить:
> • Логи работников: `/virgil` → 📊 Статус → 📜 Логи работника
> • Здоровье проекта: `/virgil` → ⚙️ Настройка → 📁 Проекты → 🩺 Проверить здоровье

## Что НЕ делать

- **Не auto-retry.** Никаких `пробую снова через 5 секунд`. Пользователь сам решает.
- **Не auto-fix.** Никаких `сейчас сам зарегистрирую проект и продолжу`. Только подсказка.
- **Не скрывать stderr.** Если шаблон не нашёлся — показать stderr дословно, не «упрощать».
- **Не загромождать.** Если знаешь pattern — короткое объяснение + 1-2 suggestion. Не выливай весь раздел документации.
- **Не предлагать `--no-verify`** или другие способы обойти safety-гейты. Если что-то отказывается работать — это намеренно.
