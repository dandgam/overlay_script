# Sub-меню «🚀 Запустить»

Загружается когда пользователь выбрал «🚀 Запустить» в главном меню. Перед вызовом CLI — прочитай `../templates/command-bridge.md`.

Вызов `AskUserQuestion`:

- **question:** «Что запускаем?»
- **header:** «Virgil → Запустить»
- **multiSelect:** false
- **options (4):**

  1. **label:** «🆕 Новый проход»
     **description:** «Запустить новый wave на одном из зарегистрированных проектов»
     **preview:** «Спрошу проект, номер прохода (например `1a`) и сколько работников параллельно»

  2. **label:** «🔄 Продолжить прерванный»
     **description:** «Найти проходы которые остановились на полпути и продолжить с того же места»
     **preview:** «Покажу список незакрытых проходов, выберешь какой возобновить»

  3. **label:** «🧪 Сухой прогон (только план, без запуска)»
     **description:** «Показать картинку зависимостей задач без реального запуска работников»
     **preview:** «ASCII-граф: какие задачи можно делать параллельно, какие должны ждать»

  4. **label:** «⏹ Остановить или пауза»
     **description:** «Пауза, продолжить после паузы, или полностью остановить текущий проход»
     **preview:** «4 варианта: мягкая пауза · продолжить · стоп после текущих задач · экстренный стоп»

## Drill-down: «🆕 Новый проход»

**Шаг 1 — выбор проекта.** Сначала вызови `Bash`: `bmad-orchestrator scan` чтобы получить список зарегистрированных проектов. Если scan вернул пустой список — предложи «➕ Зарегистрировать новый проект» как единственный путь.

Если проекты есть — вызови `AskUserQuestion`:

- **question:** «Какой target проект?»
- **header:** «Новый проход → Проект»
- **options (до 4):** до 3 проектов из scan + опция «➕ Зарегистрировать новый» (или «↩ Назад» если ≥4 проектов и нужен fallback).

Если выбрано «➕ Зарегистрировать новый» — текстовый запрос: «Введи абсолютный путь к BMad-проекту:», валидация (path exists + absolute), запуск `bmad-orchestrator init <path>`, затем продолжить с шага 2 уже зарегистрированного проекта.

Если у пользователя в исходной фразе уже было имя проекта («запусти на antares») — пропустить шаг 1, использовать заданный проект.

**Шаг 2 — wave identifier (free-text).** Отправь обычное сообщение:

> «Какой wave? (например `1a`, `2b`, `3a`). Введи в чат.»

Валидация по regex `^[1-9][a-z]?$`. При ошибке: «Wave должен быть в формате `1a`, `2b`, `3a` (цифра + опциональная буква). Попробуй ещё раз.»

**Шаг 3 — parallelism.** `AskUserQuestion`:

- **question:** «Сколько параллельных работников?»
- **header:** «Новый проход → Параллелизм»
- **options (4):**

  1. **label:** «🐢 1 — последовательно»
     **description:** «Один работник за раз. Медленно, зато ничего не сломает. Подходит для отладки»
     **preview:** «Если что-то падает — здесь будет понятнее почему. Скорость низкая»

  2. **label:** «🚶 3 — рекомендую (по умолчанию)»
     **description:** «Три работника параллельно. Хороший баланс скорости и стабильности»
     **preview:** «Большинство проходов проходят на 3-х нормально. Не требует много памяти»

  3. **label:** «🏃 4-6 — быстрее, нужно от 16ГБ памяти»
     **description:** «4, 5 или 6 работников. Спрошу точное число следом»
     **preview:** «Заметно быстрее, но память забивается. Подходит для свежей машины»

  4. **label:** «🚀 7-8 — максимум, для больших проходов»
     **description:** «7 или 8 работников. Спрошу точное число следом»
     **preview:** «Только для очень мощных машин и крупных проходов. Иначе будут тормоза»

При выборе 3 или 4 — текстовый вопрос: «Точное число работников (4-6 или 7-8)?». Валидация: целое число в диапазоне.

**Шаг 4 — подтверждение.** Покажи сборку команды в дружелюбной форме:

> «Сейчас запущу:
> • Проект: **<X>**
> • Проход: **<Y>**
> • Работников параллельно: **<N>**
>
> Что произойдёт: создам отдельную копию проекта, запущу <N> работников каждый в своей копии, после завершения проверю результат и слью обратно.
>
> Команда (для справки): `bmad-orchestrator run --project <X> --wave <Y> --max-parallel <N>`
>
> Запускаю?»

`AskUserQuestion`:
- **options (3):**
  1. **label:** «✅ Да, запускай»
  2. **label:** «✏️ Изменить параметры»  (вернуться на шаг 1)
  3. **label:** «❌ Отмена»

**Шаг 5 — выполнение.** При «Да» — вызови `Bash` с командой. Это длительная операция → используй `run_in_background: true`. Сообщи пользователю: «Запустил в фоне. Чтобы посмотреть прогресс — открой `/virgil` → 📊 Статус → 📈 Что сейчас работает. Я уведомлю когда проход завершится.»

## Drill-down: «🔄 Продолжить прерванный»

Сначала вызови `Bash`: `bmad-orchestrator scan` чтобы найти незакрытые waves. (Точный JSON формат скрипта может отличаться — если scan не показывает прерванные waves отдельно, выведи весь список и попроси пользователя указать.)

`AskUserQuestion` с найденными незакрытыми waves (до 3 опций + «↩ Назад»):

- Каждая опция (label): «<project> · проход <wave_id> — сделано <stories_done> из <stories_total> задач»
- preview: «Прерван <когда>. Продолжу с того места где остановился»

При выборе → подтверждение → `Bash`: `bmad-orchestrator resume --project X --wave Y` (длительная операция → background).

Если незакрытых waves нет: «Нет прерванных проходов. Запустить новый? (вернёмся в это sub-меню)»

## Drill-down: «🧪 Сухой прогон»

Текстовый вопрос: «Какой wave для сухого прогона? (формат `1a`)»

Валидация regex `^[1-9][a-z]?$`. Затем `Bash` (foreground, быстрая команда): `bmad-orchestrator dag --wave <wave>`. ASCII-граф приходит в stdout — стримится в чат как есть.

## Drill-down: «⏹ Остановить или пауза»

`AskUserQuestion`:

- **question:** «Какое действие?»
- **header:** «Virgil → Остановить»
- **options (4):**

  1. **label:** «⏸ Пауза — мягкая»
     **description:** «Работники доделают текущую задачу и остановятся. Потом можно продолжить»
     **preview:** «Безопасно. Никакая работа не потеряется. Подходит когда нужно отвлечь машину»

  2. **label:** «▶️ Продолжить после паузы»
     **description:** «Снять паузу. Работники продолжат с того места где остановились»
     **preview:** «Используй после кнопки «Пауза» когда готов работать дальше»

  3. **label:** «🛑 Стоп — после текущих задач ⚠»
     **description:** «Подождать пока работники закроют то что начали, и закончить проход. Нужно подтверждение»
     **preview:** «Безопасно но необратимо: проход помечается как остановленный»

  4. **label:** «💥 Экстренный стоп — немедленно ⚠⚠»
     **description:** «Убить всех работников прямо сейчас. Несохранённая работа потеряется. Нужно подтверждение»
     **preview:** «Только если зависло и не реагирует на обычный стоп. Потеряется час-два работы»

- Опции 1, 2 → прямой `Bash` (foreground): `bmad-orchestrator pause` / `bmad-orchestrator resume`.
- Опции 3, 4 → **destructive confirm placeholder**:

  Покажи `AskUserQuestion`:
  - **question:** «⚠ Внимание — необратимое действие. Подтверждаешь?»
  - В тексте вопроса описать последствия простыми словами:
    - Для «Стоп после текущих задач»: «Проход остановится после того как работники закроют начатые задачи. Возобновить его потом нельзя — только запустить заново.»
    - Для «Экстренный стоп»: «Все работники убиваются немедленно. Несохранённая работа за последний час-два потеряется безвозвратно.»
  - **options (2):**
    1. **label:** «⛔ Отменить» (рекомендуется)
    2. **label:** «✅ Подтвердить и остановить»
  - При выборе «Подтвердить» — `Bash`: `bmad-orchestrator stop --graceful` или `stop --hard`. **Примечание:** в Session 3 этот упрощённый вариант заменится на двухшаговое подтверждение (ввод фразы текстом, см. `../templates/confirm-destructive.md`).
