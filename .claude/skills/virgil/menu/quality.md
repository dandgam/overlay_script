# Sub-меню «🧪 Качество и обучение»

Загружается когда пользователь выбрал «🧪 Качество и обучение» в главном меню. Перед вызовом CLI — прочитай `../templates/command-bridge.md` (там полный путь к `bmad-orchestrator`).

Вызов `AskUserQuestion`:

- **question:** «Что делаем?»
- **header:** «Virgil → Качество»
- **multiSelect:** false
- **options (4):**

  1. **label:** «🧪 Тесты (eval)»
     **description:** «Прогнать набор проверок и узнать процент успешных прохождений»
     **preview:** «Дешёвый mock-режим или настоящий real (тратит токены)»

  2. **label:** «🧬 Самообучение»
     **description:** «Чему агент научился, запустить обучение, отправить уроки на разбор, откатить»
     **preview:** «База self-learning: уроки, применённые правки, откаты»

  3. **label:** «🧭 Корректировка курса»
     **description:** «Поменять задачу на ходу — сменился scope или критерии приёмки»
     **preview:** «Спрошу номер задачи и причину»

  4. **label:** «🔬 Расследование инцидента»
     **description:** «Глубокий разбор: задача-проблема, класс ошибки, инцидент»
     **preview:** «Спрошу что расследуем и почему»

## Drill-down: «🧪 Тесты (eval)»

**Шаг 1 — режим.** `AskUserQuestion`:
- **options (2):**
  1. **label:** «🎭 Mock — бесплатно, быстро»
     **description:** «Синтетические проверки без настоящего запуска Claude. Не тратит токены»
     **preview:** «Подходит для регулярной проверки что ничего не сломалось»
  2. **label:** «🌍 Real — настоящий прогон»
     **description:** «Запускает реальный claude. Тратит токены, идёт дольше»
     **preview:** «Для честного замера качества перед важным запуском»

**Шаг 2 — объём.** `AskUserQuestion`:
- **options (3):**
  1. **label:** «📦 Все проверки»
     **description:** «Прогнать весь набор cases»
     **preview:** «bmad-orchestrator eval run»
  2. **label:** «🎯 Один case»
     **description:** «Прогнать только одну проверку по её id»
     **preview:** «Спрошу id (например `TC-001`)»
  3. **label:** «↩ Назад»
     **description:** «Вернуться в меню Качество»
     **preview:** «Возврат на шаг назад»

**Шаг 3 — выполнение.** Сборка: `bmad-orchestrator eval run [--case <id>] --mode <mock|real>`.
- Mock — foreground (быстро). Real — `run_in_background: true` (долго).
- После — показать `pass_rate` простым языком: «Прошло X из Y проверок (NN%)».

## Drill-down: «🧬 Самообучение»

Virgil после каждого прохода извлекает уроки (что сработало, что нет) и предлагает правки policy.

`AskUserQuestion`:

- **question:** «Что с обучением?»
- **header:** «Качество → Самообучение»
- **options (4):**

  1. **label:** «📚 Чему научился»
     **description:** «Список: извлечённые уроки, применённые правки, откаченные изменения»
     **preview:** «Соберу всё что Virgil усвоил за прошлые проходы»

  2. **label:** «▶️ Запустить обучение сейчас»
     **description:** «Прогнать цикл self-learning вручную, не дожидаясь расписания»
     **preview:** «Virgil перечитает свежие уроки и предложит правки policy»

  3. **label:** «🔬 Отправить на разбор в 888»
     **description:** «Передать уроки в скилл /888 для мета-анализа методички»
     **preview:** «888 скажет какие пробелы вскрывают эти уроки»

  4. **label:** «↩️ Откатить правку»
     **description:** «Вернуть назад ранее применённую правку policy по её id»
     **preview:** «Спрошу id из audit-лога. Безопасно — восстановит из бэкапа»

### «📚 Чему научился»

Собрать в один читаемый список: статус self-learning + извлечённые уроки + состояние правок.

1. `Bash` (foreground): `bmad-orchestrator self-learning status` — включён ли self-learning, конфигурация, последний прогон.
2. Урок-файлы: `skills/lessons/<project>/wave-<N>.md` (по одному `.md` на проход). `Bash`: `ls skills/lessons/*/`. Содержимое конкретного — через `Read`.
3. Предложенные правки: `_config/projects/<slug>/policy-proposals.yaml`. `Bash`: `ls _config/projects/*/policy-proposals.yaml 2>/dev/null`, при наличии — `Read`.
4. Сведи простым языком: сколько уроков и из каких проходов; какие правки предложены/применены/откачены; включён ли self-learning.

Если файлов нет — «Virgil пока ничему не научился — не было завершённых проходов с retrospective».

**Точные пути не выдумывать** — зафиксированы в `src/bmad_orchestrator/runtime/lesson_parser.py` (`parse_lessons_dir`, `proposals_yaml_path`).

### «▶️ Запустить обучение сейчас»

Подтверждение (`AskUserQuestion` Да / Отмена), затем `Bash` (foreground): `bmad-orchestrator self-learning run`. Поясни простым языком что произошло.

### «🔬 Отправить на разбор в 888»

1. Собери уроки в краткий бриф (как в «📚 Чему научился» шаги 1-3): уроки + правки. Бриф ≤2000 слов — выжимка, не сырые файлы.
2. Вызови скилл `/888` через **Skill tool** (`skill: "888"`) с задачей:

   > «Вот чему научился агент Virgil (bmad-orchestrator) за прошлые проходы — уроки и предложенные правки policy. Сделай meta-review в режиме gap-analysis: что эти уроки говорят о методичке построения агентов, какие пробелы вскрывают, что добавить в REFERENCE.md или templates. Бриф ниже:\n\n<бриф уроков>»

3. После `/888` — вернуть пользователя в это sub-меню.

Если уроков нет — «Нечего отправлять — база self-learning пуста», `/888` не вызывать.

### «↩️ Откатить правку»

1. Текстовый вопрос: «Введи id правки для отката (timestamp из audit-лога self-learning):». Валидация — непустая строка.
2. Подсказка: если id неизвестен — глянь «📚 Чему научился».
3. **Двухшаговое подтверждение** — прочитай `../templates/confirm-destructive.md`, фраза `ROLLBACK LEARNING`.
4. При успехе → `Bash` (foreground): `bmad-orchestrator self-learning rollback <id>`.
5. Результат: успех — «Откат выполнен»; ошибка — прочитай `../templates/error-handling.md` для разбора.

## Drill-down: «🧭 Корректировка курса»

Используется когда у задачи на ходу сменился scope или критерии приёмки.

Два текстовых вопроса:
1. «Номер задачи? (например `1.1`)» — regex `^[0-9]+\.[0-9]+$`
2. «Причина? (например: PM убрал часть scope, поменялись критерии приёмки)» — непустая строка

Затем `AskUserQuestion` режим: «🎭 Mock (без запуска claude)» / «🌍 Real (запустить разбор)».

`Bash`: `bmad-orchestrator correct-course --story <id> --reason "<reason>" --mock` (или `--real`).

## Drill-down: «🔬 Расследование инцидента»

Глубокий форензик-разбор проблемы.

Два текстовых вопроса:
1. «Что расследуем? (id задачи, класс ошибки или название инцидента)» — непустая строка
2. «Почему расследуем? (краткое описание)» — непустая строка

Затем `AskUserQuestion` режим: «🎭 Mock» / «🌍 Real».

`Bash`: `bmad-orchestrator investigate --subject "<subject>" --reason "<reason>" --mock` (или `--real`). Ручной запуск по умолчанию `--force` (минует эвристику счётчика повторов) — флаг можно не добавлять явно, это default CLI.
